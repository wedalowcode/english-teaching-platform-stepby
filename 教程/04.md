# 第四篇：使用 Git 管理项目版本，并推送到 GitHub

前面三篇，我们已经完成了开发环境准备、Next.js 项目初始化，以及管理后台基础布局。

随着项目不断开发，代码文件会越来越多，功能也会越来越复杂。

如果某次修改导致系统无法运行，应该如何恢复？

如果 AI 修改了几十个文件，如何知道它具体改了什么？

如果需要在另一台电脑上继续开发，如何获取完整的项目代码？

这些问题都需要通过版本管理来解决。

本篇开始使用 Git 管理项目，并将代码托管到 GitHub。

最终实现：

1. 在本地项目中初始化 Git 仓库。
2. 理解 Git 的基本工作流程。
3. 创建 `.gitignore`，排除不需要提交的文件。
4. 将当前代码提交为第一个版本。
5. 在 GitHub 创建远程仓库。
6. 将本地代码推送到 GitHub。
7. 验证远程仓库中的代码是否完整。

## 一、先理解 Git 和 GitHub

### 1.1 什么是 Git？

Git 是一个分布式版本控制系统。

简单来说，它可以帮助我们记录项目代码在不同时间点的状态。

例如，英语教学平台的开发过程可能是：

```text
版本1：初始化 Next.js 项目
   ↓
版本2：完成管理后台布局
   ↓
版本3：完成用户管理列表
   ↓
版本4：完成用户新增
   ↓
版本5：完成用户编辑
```

每完成一个相对独立的功能，我们都可以创建一个版本。

如果后续发现版本5有问题，可以查看版本4的代码，分析差异，必要时恢复之前的状态。

Git 管理的是代码的变化，而不是简单地保存多个文件夹副本。

### 1.2 什么是 GitHub？

Git 是版本管理工具，GitHub 是代码托管平台。

两者不是同一个东西。

| 名称 | 作用 |
|---|---|
| Git | 在本地管理代码版本 |
| GitHub | 在远程服务器托管 Git 仓库 |
| Git 仓库 | 保存项目文件及其版本记录 |
| 远程仓库 | 托管在 GitHub 等平台上的仓库 |

可以这样理解：

- Git 负责记录代码历史。
- GitHub 负责保存远程代码仓库。
- 本地电脑和 GitHub 之间通过 Git 命令同步代码。

除了 GitHub，还存在 GitLab、Gitee 等代码托管平台。本篇统一使用 GitHub。

### 1.3 Git 的基本工作流程

Git 最重要的概念是三个区域：

```text
工作区
  │
  │ git add
  ▼
暂存区
  │
  │ git commit
  ▼
本地仓库
  │
  │ git push
  ▼
GitHub 远程仓库
```

分别理解：

**工作区（Working Tree）**

就是我们当前正在编写代码的项目目录。

例如，修改 `config/menu.ts`，这个修改首先发生在工作区。

**暂存区（Staging Area）**

准备提交的代码需要先放到暂存区。

通过 `git add` 命令，将指定文件的修改加入暂存区。

**本地仓库（Local Repository）**

通过 `git commit` 命令，将暂存区中的内容保存为一个版本。

这个版本保存在本地 Git 仓库中。

**远程仓库（Remote Repository）**

通过 `git push` 命令，将本地提交推送到 GitHub。

需要注意：`git add` 不会创建版本，`git commit` 才会创建本地版本，`git push` 才会将本地提交同步到远程仓库。

### 1.4 本篇需要掌握的 Git 命令

| 命令 | 作用 |
|---|---|
| `git init` | 初始化本地仓库 |
| `git status` | 查看当前工作区状态 |
| `git add` | 将修改加入暂存区 |
| `git commit` | 创建本地版本 |
| `git log` | 查看版本提交记录 |
| `git remote` | 管理远程仓库地址 |
| `git push` | 推送代码到远程仓库 |
| `git pull` | 从远程仓库拉取并整合代码 |
| `git diff` | 查看代码修改差异 |

这些命令是后续开发过程中最常用的 Git 基础操作。

## 二、第一步：安装并检查 Git

如果前面已经安装过 Git，可以直接检查版本。

打开终端，执行：

```bash
git --version
```

如果正常安装，会输出类似：

```text
git version 2.x.x
```

如果提示找不到命令，需要先安装 Git。

Windows 用户可以访问：

https://git-scm.com/downloads

下载 Windows 版本并完成安装。

安装完成后，重新打开终端，再次执行：

```bash
git --version
```

确认 Git 可以正常使用。

## 三、第二步：配置 Git 用户信息

Git 在创建版本时，需要记录提交者的信息。

第一次使用 Git，需要配置用户名和邮箱。

执行：

```bash
git config --global user.name "你的用户名"
```

再执行：

```bash
git config --global user.email "你的邮箱"
```

例如：

```bash
git config --global user.name "wedalowcode"
git config --global user.email "your-email@example.com"
```

这里的用户名和邮箱用于标记代码提交者。

建议使用 GitHub 账户关联的邮箱，以便 GitHub 正确识别提交记录。

注意：这里的邮箱只是提交记录中的身份信息，不是 GitHub 登录密码。

配置完成后，可以查看：

```bash
git config --global --list
```

正常情况下，可以看到刚才配置的用户名和邮箱。

## 四、第三步：在项目中初始化 Git 仓库

现在进入英语教学平台项目的根目录。

注意：必须进入包含 `package.json` 的项目目录，而不是它的上级目录。

例如：

```bash
cd D:\project\english-teaching-platform
```

实际执行时，替换成自己的项目路径。

可以通过以下命令确认当前目录：

```bash
dir
```

应该能看到：

```text
package.json
pnpm-lock.yaml
app
components
config
```

确认目录正确后，执行：

```bash
git init
```

这个命令会在当前项目目录中创建一个隐藏的 `.git` 目录。

这个目录用于保存 Git 仓库的版本信息。

执行完成后，可以看到类似提示：

```text
Initialized empty Git repository ...
```

说明本地 Git 仓库已经初始化。

### 4.1 什么是分支？

初始化 Git 仓库后，还需要理解一个概念：分支。

分支可以理解为项目开发过程中的一条独立代码线。

例如：

```text
main
 │
 ├── 用户管理
 │
 ├── 学生管理
 │
 └── 教师管理
```

Git 仓库可以创建多个分支，让不同功能在不同代码线上开发。

本篇暂时不涉及复杂的分支协作，统一使用 `main` 作为主分支。

执行：

```bash
git branch -M main
```

这个命令会将当前分支名称设置为 `main`。

后续所有基础开发版本先提交到这个分支。

## 五、第四步：配置 .gitignore

在正式提交代码之前，需要先解决一个问题：

项目中并不是所有文件都应该提交到 GitHub。

例如：

- `node_modules`：项目安装的依赖包。
- `.next`：Next.js 运行和构建产生的缓存文件。
- `.env`：可能包含数据库连接地址、密钥等敏感信息。
- `dist`：构建输出目录。

这些文件没有必要全部上传到远程仓库。

尤其是环境变量文件，如果包含数据库密码或其他密钥，不能直接提交到公开仓库。

### 5.1 什么是 .gitignore？

`.gitignore` 是 Git 提供的忽略规则文件。

我们可以在其中指定不需要 Git 跟踪的文件和目录。

在项目根目录创建：

```text
.gitignore
```

如果初始化 Next.js 时已经生成了这个文件，不需要重新创建，直接检查并补充即可。

### 5.2 编写完整配置

建议使用以下配置：

```gitignore
# Dependencies
node_modules/

# Next.js
.next/
out/

# Build output
dist/
build/

# Environment variables
.env
.env.*
!.env.example

# Logs
*.log
npm-debug.log*
pnpm-debug.log*

# Editor
.vscode/
.idea/

# OS
.DS_Store
Thumbs.db
```

### 5.3 理解忽略规则

例如：

```gitignore
node_modules/
```

表示忽略 `node_modules` 目录及其内容。

```gitignore
.next/
```

表示忽略 Next.js 生成的缓存和构建目录。

```gitignore
.env
.env.*
```

表示忽略环境变量文件。

但：

```gitignore
!.env.example
```

表示重新允许提交 `.env.example` 文件。

为什么要保留 `.env.example`？

因为后续项目可能需要数据库连接地址等配置。

真正的 `.env` 不应该提交，但可以提供一个不包含真实密码的示例文件，告诉其他开发者需要配置哪些环境变量。

注意：`.gitignore` 只对尚未被 Git 跟踪的文件生效。如果某个敏感文件之前已经提交过，仅仅增加忽略规则并不能将它从历史记录中清除。

## 六、第五步：提交第一个版本

现在可以将项目代码提交到本地 Git 仓库。

### 6.1 查看当前状态

执行：

```bash
git status
```

Git 会列出当前尚未被跟踪的文件，以及已经发生修改的文件。

例如：

```text
Untracked files:
  app/
  components/
  config/
  package.json
```

这些文件目前还没有被 Git 正式跟踪。

### 6.2 将代码加入暂存区

执行：

```bash
git add .
```

这里的 `.` 表示当前目录下符合 Git 跟踪规则的文件。

Git 会将这些文件加入暂存区。

然后再次执行：

```bash
git status
```

这时可以看到文件已经进入暂存状态。

### 6.3 创建第一个版本

执行：

```bash
git commit -m "初始化英语教学平台项目"
```

其中：

- `git commit` 表示创建一次本地提交。
- `-m` 用于填写本次提交说明。
- 引号中的文字是本次版本的描述。

执行完成后，Git 就会保存当前暂存区中的代码状态。

### 6.4 查看版本记录

执行：

```bash
git log --oneline
```

正常情况下，会看到类似：

```text
a1b2c3d 初始化英语教学平台项目
```

前面是一段提交 ID，后面是提交说明。

至此，项目已经有了第一个本地版本。

注意：现在代码还只保存在本地电脑中，还没有上传到 GitHub。

## 七、第六步：在 GitHub 创建远程仓库

接下来打开 GitHub：

https://github.com/

登录自己的 GitHub 账号。

### 7.1 创建仓库

点击右上角的 `+`，选择：

```text
New repository
```

进入仓库创建页面。

填写以下信息：

| 配置项 | 内容 |
|---|---|
| Repository name | english-teaching-platform |
| Description | 英语教学平台全栈实战项目 |
| Visibility | Public 或 Private |
| Add a README file | 不勾选 |
| Add .gitignore | 不选择 |
| Choose a license | 暂不选择 |

这里为什么不勾选 README？

因为我们已经在本地创建了 Git 仓库，并且准备将本地代码作为第一个版本推送上去。

如果远程仓库提前创建了 README，就会产生一个独立的远程提交。第一次推送时可能需要先处理两个仓库的提交历史。

本篇为了简化操作，先创建一个空仓库。

最后点击：

```text
Create repository
```

### 7.2 复制远程仓库地址

创建完成后，GitHub 会显示仓库地址。

选择 HTTPS，复制仓库地址。

地址形式类似：

```text
https://github.com/你的用户名/english-teaching-platform.git
```

注意：这里的 `你的用户名` 要替换成自己的 GitHub 用户名。

接下来需要把这个地址配置到本地 Git 仓库中。

## 八、第七步：关联远程仓库并推送代码

回到本地项目终端。

### 8.1 添加远程仓库

执行：

```bash
git remote add origin https://github.com/你的用户名/english-teaching-platform.git
```

这里：

- `remote` 表示管理远程仓库。
- `add` 表示添加远程仓库。
- `origin` 是远程仓库的默认名称。
- 后面的地址是 GitHub 仓库地址。

为什么叫 `origin`？

这是 Git 中非常常见的远程仓库别名。

它不是固定名称，但大多数项目都会使用 `origin`。

### 8.2 查看远程仓库配置

执行：

```bash
git remote -v
```

如果配置正确，会看到类似：

```text
origin  https://github.com/你的用户名/english-teaching-platform.git (fetch)
origin  https://github.com/你的用户名/english-teaching-platform.git (push)
```

说明本地仓库已经关联到 GitHub 远程仓库。

### 8.3 推送代码

执行：

```bash
git push -u origin main
```

这条命令是本篇最重要的命令之一。

拆开理解：

- `git push`：将本地提交推送到远程仓库。
- `origin`：指定远程仓库。
- `main`：指定要推送的本地分支。
- `-u`：建立本地分支与远程分支之间的跟踪关系。

第一次推送时使用 `-u`。

以后在当前分支上提交新版本，可以直接执行：

```bash
git push
```

Git 就知道应该将代码推送到哪个远程分支。

### 8.4 GitHub 身份验证

第一次推送时，可能会要求进行身份验证。

按照 GitHub 的提示完成浏览器授权即可。

如果终端提示需要输入账号密码，需要注意：GitHub 已不支持使用普通账户密码进行 Git HTTPS 操作。

可以使用 Git Credential Manager 等凭据管理工具完成认证，也可以使用 SSH 方式连接。

本篇优先采用 HTTPS，按照实际认证提示完成授权。

## 九、第八步：验证远程仓库

代码推送完成后，重新打开 GitHub 仓库页面。

刷新页面，应该可以看到：

```text
english-teaching-platform
│
├── app/
├── components/
├── config/
├── package.json
├── pnpm-lock.yaml
└── ...
```

同时可以看到刚才提交的版本说明：

```text
初始化英语教学平台项目
```

这说明本地代码已经成功推送到 GitHub。

还可以在本地执行：

```bash
git status
```

如果显示：

```text
nothing to commit, working tree clean
```

表示当前工作区没有尚未提交的修改。

至此，本地 Git 仓库和 GitHub 远程仓库已经建立关联。

## 十、以后开发如何保存版本？

本篇完成的是第一次提交。

后续每开发一个功能，都可以使用相同的流程。

例如，完成用户管理列表后：

### 10.1 查看修改

```bash
git status
```

### 10.2 查看具体代码差异

```bash
git diff
```

`git diff` 可以查看工作区中尚未暂存的代码修改。

这样可以检查 AI 修改了哪些文件、增加了哪些代码、删除了哪些代码。

### 10.3 将修改加入暂存区

```bash
git add .
```

### 10.4 提交新版本

```bash
git commit -m "完成用户管理列表"
```

### 10.5 推送到 GitHub

```bash
git push
```

整个流程就是：

```text
修改代码
   ↓
git status
   ↓
git diff
   ↓
git add .
   ↓
git commit
   ↓
git push
```

建议每完成一个相对独立的功能，就创建一次提交。

例如：

```text
初始化英语教学平台项目
完成管理后台基础布局
完成用户管理列表
完成用户新增
完成用户编辑
完成用户删除
```

这样，项目就有了一条清晰的开发历史。

## 十一、本篇总结

本篇完成了项目的第一次版本管理。

我们使用 Git 在本地建立仓库，通过 `git add`、`git commit` 保存代码版本，再通过 `git remote` 和 `git push` 将代码推送到 GitHub。

需要记住三个核心动作：

- `git add`：选择要提交的代码。
- `git commit`：在本地保存一个版本。
- `git push`：将本地版本推送到远程仓库。

对于 AI 辅助开发，这套机制尤其重要。

AI 可以快速修改大量代码，但代码修改越快，越需要版本管理。

每次让 AI 完成一个相对独立的功能，都应该先检查修改内容，确认没有问题后再提交版本。

**Git 不只是代码备份工具，更是 AI 辅助开发过程中的安全边界。**

从本篇开始，后续每篇教程完成一个阶段性功能，都要通过 Git 保存版本，逐步形成完整、可追溯的项目开发历史。
