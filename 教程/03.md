# 第三篇：搭建管理后台基础布局，实现左右分栏

第二篇我们已经完成了 Next.js 项目的初始化，并安装了 Zod。

从本篇开始，正式搭建英语教学平台的管理后台。

在真正开发用户管理、学生管理、课程管理等业务功能之前，需要先搭建一个公共页面框架。后续所有业务页面都在这个框架中展示，不需要每个页面重复编写导航菜单和布局结构。

本篇只完成基础布局，不涉及登录认证、权限控制和数据库操作。

最终实现的效果是：

- 左侧显示管理后台菜单。
- 右侧显示页面内容。
- 点击菜单可以切换页面。
- 访问网站根地址时，自动跳转到用户管理页面。
- 用户管理页面先显示简单的标题和说明文字。

## 一、先理解管理后台的整体结构

### 1.1 管理后台页面由哪些部分组成？

先看一下本篇要实现的页面结构：

```text
┌──────────────────────────────────────────────────────┐
│                                                      │
│  ┌──────────────┐  ┌──────────────────────────────┐  │
│  │              │  │                              │  │
│  │              │  │  管理后台                    │  │
│  │              │  ├──────────────────────────────┤  │
│  │              │  │                              │  │
│  │  英语教学平台│  │                              │  │
│  │              │  │                              │  │
│  │  用户管理    │  │       用户管理               │  │
│  │              │  │                              │  │
│  │              │  │       用户列表将在这里展示   │  │
│  │              │  │                              │  │
│  │              │  │                              │  │
│  └──────────────┘  └──────────────────────────────┘  │
│                                                      │
└──────────────────────────────────────────────────────┘
```

整个页面可以分成三个区域：

1. **左侧导航区域**：展示系统名称和功能菜单。
2. **右侧顶部区域**：展示管理后台名称。
3. **右侧内容区域**：展示当前访问的业务页面。

为什么要这样划分？

假设后续系统增加了学生管理、教师管理、词汇管理等功能。

这些页面都需要左侧导航。如果每个页面都单独写一遍左侧导航，就会产生大量重复代码。

更合理的方式是：把公共布局单独提取出来，业务页面只负责自己的内容。

### 1.2 需要创建哪些文件？

本篇涉及的文件结构如下：

```text
app/
├── layout.tsx
├── page.tsx
└── (dashboard)/
    ├── layout.tsx
    └── admin/
        └── users/
            └── page.tsx

components/
├── layout/
│   └── admin-sidebar.tsx
└── ui/
    └── sidebar.tsx

config/
└── menu.ts
```

各文件的职责：

| 文件 | 作用 |
|---|---|
| `app/layout.tsx` | Next.js 应用根布局，由项目初始化时生成 |
| `app/page.tsx` | 网站根页面，负责跳转到用户管理 |
| `app/(dashboard)/layout.tsx` | 管理后台公共布局 |
| `app/(dashboard)/admin/users/page.tsx` | 用户管理页面 |
| `components/layout/admin-sidebar.tsx` | 左侧导航组件 |
| `components/ui/sidebar.tsx` | shadcn 生成的 Sidebar 基础组件 |
| `config/menu.ts` | 菜单配置数据 |

这里有两个目录需要特别理解：

**app 目录：** Next.js 约定的路由目录，主要负责页面和布局组织。

**components 目录：** 存放可以复用的 React 组件，例如左侧导航。

我们把菜单配置放在 `config` 目录中，是因为菜单数据本身不属于某个页面，也不属于某个具体的界面组件。

### 1.3 页面是如何组合起来的？

本篇采用 Next.js App Router 的 Layout 机制。

整体关系如下：

```text
app/layout.tsx
    │
    └── app/(dashboard)/layout.tsx
            │
            ├── AdminSidebar
            │       │
            │       └── config/menu.ts
            │
            └── 右侧内容区域
                    │
                    └── children
                            │
                            └── 用户管理页面
```

其中最重要的是 `children`。

它代表当前 Layout 所包裹的页面内容。

例如访问 `/admin/users` 时，用户管理页面会作为 `children` 显示在右侧内容区。

以后增加其他页面时，也可以复用同一个 Layout。

## 二、实现之前需要掌握的知识

本篇会使用 Next.js、React、TypeScript 和 shadcn。先理解完成本篇所需要的基础概念。

### 2.1 Next.js：什么是 App Router？

Next.js 使用文件系统组织路由。

简单来说，`app` 目录中的文件和文件夹可以按照约定生成网站路由。

例如：

```text
app/
└── admin/
    ├── page.tsx
    └── users/
        └── page.tsx
```

对应的访问地址：

| 文件 | 访问地址 |
|---|---|
| `admin/page.tsx` | `/admin` |
| `admin/users/page.tsx` | `/admin/users` |

其中 `page.tsx` 是 Next.js 约定的页面文件。

当用户访问对应地址时，Next.js 会加载对应的页面组件。

### 2.2 Next.js：什么是 Layout？

除了 `page.tsx`，Next.js 还有一个非常重要的文件：`layout.tsx`。

它用于定义多个页面共享的布局。

例如：

```tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div>
      <aside>左侧菜单</aside>

      <main>
        <header>顶部区域</header>

        {children}
      </main>
    </div>
  );
}
```

这里的 `children` 表示当前布局中的子页面。

假设访问 `/admin/users`，那么用户管理页面就会放到 `{children}` 的位置。

如果以后访问 `/admin/students`，学生管理页面也会放到同一个位置。

因此，Layout 的作用就是：**把公共界面固定下来，让不同业务页面在指定区域切换。**

### 2.3 Next.js：什么是路由分组？

本篇会使用这样的目录：

```text
app/
└── (dashboard)/
    └── admin/
        └── users/
            └── page.tsx
```

其中 `(dashboard)` 是 Next.js 的路由分组语法。

目录名称使用括号包裹后，不会出现在最终访问地址中。

所以：

```text
app/(dashboard)/admin/users/page.tsx
```

对应的访问地址仍然是：

```text
/admin/users
```

为什么要使用路由分组？

因为以后可能还有登录页面、公开页面等不同类型的页面，它们不一定需要相同的布局。

通过路由分组，可以把需要共享同一套布局的页面组织在一起。

本篇先把管理后台页面放在 `(dashboard)` 分组中。

### 2.4 React：什么是组件？

React 使用组件来组织界面。

一个组件可以理解为一个独立的界面单元。

例如：

```tsx
function Welcome() {
  return <h1>欢迎使用英语教学平台</h1>;
}
```

这里定义了一个名为 `Welcome` 的组件。

在其他组件中，可以这样使用：

```tsx
<Welcome />
```

本篇会把左侧菜单单独定义成 `AdminSidebar` 组件。

这样做的好处是，布局文件只需要负责组织页面结构，左侧菜单的具体实现放在自己的文件中。

### 2.5 React：什么是 JSX？

前面的代码中出现了这样的写法：

```tsx
return (
  <div>
    <h1>用户管理</h1>
    <p>用户列表将在这里展示。</p>
  </div>
);
```

这不是普通的 HTML，而是 JSX。

JSX 是 React 用来描述界面的语法，可以在 JavaScript 或 TypeScript 代码中编写类似 HTML 的结构。

需要注意：

- JSX 必须有一个共同的根节点。
- HTML 的 `class` 属性在 JSX 中使用 `className`。
- JavaScript 表达式可以通过 `{}` 放入 JSX。

例如：

```tsx
const title = "用户管理";

return <h1>{title}</h1>;
```

这里 `{title}` 会显示变量中的内容。

### 2.6 TypeScript：什么是类型定义？

TypeScript 在 JavaScript 的基础上增加了类型系统。

例如：

```ts
const name: string = "张三";

const age: number = 18;

const enabled: boolean = true;
```

其中：

- `string` 表示字符串。
- `number` 表示数字。
- `boolean` 表示布尔值。

还可以使用 `type` 定义对象结构：

```ts
type MenuItem = {
  title: string;
  href: string;
};
```

这表示菜单项必须包含：

- `title`：字符串。
- `href`：字符串。

后续创建菜单数据时，TypeScript 就会检查数据结构是否符合定义。

### 2.7 TypeScript：什么是数组类型？

菜单不止一项，因此需要使用数组。

例如：

```ts
const menus: MenuItem[] = [
  {
    title: "用户管理",
    href: "/admin/users",
  },
  {
    title: "学生管理",
    href: "/admin/students",
  },
];
```

`MenuItem[]` 表示这是一个数组，数组中的每一项都必须符合 `MenuItem` 类型。

在界面中，可以使用 `map()` 遍历数组：

```tsx
{menus.map((item) => (
  <div key={item.href}>
    {item.title}
  </div>
))}
```

`map()` 会逐项遍历数组，并将每一项转换成对应的 JSX 元素。

`key` 用于帮助 React 识别列表中的每一项。

### 2.8 shadcn：什么是组件库？

本篇使用 shadcn 的 Sidebar 组件实现左侧导航。

shadcn/ui 是一套基于 React 的 UI 组件方案，提供按钮、输入框、对话框、侧边栏等常见界面组件。

它和传统组件库有一个区别：

shadcn 会把组件代码添加到我们自己的项目中，通常放在 `components/ui` 目录下。

因此，我们可以直接查看组件的实现，也可以根据项目需要进行修改。

不过，第二篇还没有安装 shadcn，本篇需要先完成安装。

### 2.9 shadcn：组件如何使用？

shadcn 组件的使用方式和普通 React 组件类似。

首先导入：

```tsx
import { Button } from "@/components/ui/button";
```

然后在 JSX 中使用：

```tsx
<Button>
  新增用户
</Button>
```

如果组件支持不同样式，还可以通过属性设置：

```tsx
<Button variant="outline">
  取消
</Button>
```

本篇使用的 Sidebar 也是这种方式。

它不是一个单独的组件，而是由多个组件组合而成。

| 组件 | 作用 |
|---|---|
| `SidebarProvider` | 提供侧边栏状态管理 |
| `Sidebar` | 侧边栏主体 |
| `SidebarHeader` | 侧边栏头部 |
| `SidebarContent` | 侧边栏内容区域 |
| `SidebarGroup` | 菜单分组 |
| `SidebarMenu` | 菜单列表 |
| `SidebarMenuItem` | 单个菜单项 |
| `SidebarMenuButton` | 菜单按钮 |
| `SidebarInset` | 右侧主内容区域 |
| `SidebarTrigger` | 展开或收起侧边栏 |

这些组件组合起来，就能形成完整的管理后台框架。

### 3.4 理解 Sidebar 的基本组合方式

在编写自己的组件之前，先看一个最简单的 Sidebar 结构：

```tsx
<SidebarProvider>
  <Sidebar>
    <SidebarHeader>
      管理后台
    </SidebarHeader>

    <SidebarContent>
      <SidebarGroup>
        <SidebarMenu>
          <SidebarMenuItem>
            <SidebarMenuButton>
              用户管理
            </SidebarMenuButton>
          </SidebarMenuItem>
        </SidebarMenu>
      </SidebarGroup>
    </SidebarContent>
  </Sidebar>

  <SidebarInset>
    页面内容
  </SidebarInset>
</SidebarProvider>
```

理解它的层级关系：

```text
SidebarProvider
│
├── Sidebar
│   ├── SidebarHeader
│   └── SidebarContent
│       └── SidebarGroup
│           └── SidebarMenu
│               └── SidebarMenuItem
│                   └── SidebarMenuButton
│
└── SidebarInset
```

这里有一个重要原则：

**SidebarProvider 是整个侧边栏体系的外层环境，Sidebar 和 SidebarInset 是左右两个主要区域。**

后面我们会在这个结构上增加菜单数据和页面跳转。

## 四、第二步：创建菜单配置文件

首先创建目录：

```text
config/
```

然后在目录中创建：

```text
config/menu.ts
```

这个文件只负责定义菜单数据，不负责显示界面。

为什么单独创建菜单配置？

因为菜单内容和菜单的显示方式应该分离。

以后增加学生管理、教师管理等菜单，只需要修改这个配置文件，不需要重新修改侧边栏的整体结构。

### 4.1 编写完整代码

在 `config/menu.ts` 中写入：

```ts
export type MenuItem = {
  title: string;
  href: string;
  icon: string;
};

export const adminMenus: MenuItem[] = [
  {
    title: "用户管理",
    href: "/admin/users",
    icon: "users",
  },
];
```

### 4.2 理解代码

首先：

```ts
export type MenuItem = {
  title: string;
  href: string;
  icon: string;
};
```

定义了菜单项的数据结构。

其中：

- `title` 表示菜单名称。
- `href` 表示点击菜单后访问的地址。
- `icon` 表示菜单使用的图标名称。

这里使用 `export`，表示其他文件可以导入这个类型。

接下来：

```ts
export const adminMenus: MenuItem[] = [
  {
    title: "用户管理",
    href: "/admin/users",
    icon: "users",
  },
];
```

定义实际菜单数据。

`adminMenus` 是一个 `MenuItem[]` 类型的数组。

也就是说，数组中的每一个对象都必须符合前面定义的结构。

目前先配置一个用户管理菜单。

后续增加菜单时，只需要继续向数组中添加对象。

例如：

```ts
{
  title: "学生管理",
  href: "/admin/students",
  icon: "users",
}
```

本篇暂时不增加其他菜单，因为对应业务页面还没有实现。

## 五、第三步：创建左侧导航组件

接下来创建目录：

```text
components/layout/
```

在目录中创建文件：

```text
components/layout/admin-sidebar.tsx
```

这个组件负责将菜单配置转换成真正的左侧导航界面。

它需要完成三件事：

1. 读取菜单配置。
2. 根据菜单配置生成菜单项。
3. 点击菜单时跳转到对应页面，并根据当前地址显示选中状态。

### 5.1 编写完整代码

在 `admin-sidebar.tsx` 中写入：

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import { Users } from "lucide-react";

import {
  Sidebar,
  SidebarContent,
  SidebarGroup,
  SidebarHeader,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
} from "@/components/ui/sidebar";

import { adminMenus } from "@/config/menu";

export function AdminSidebar() {
  const pathname = usePathname();

  return (
    <Sidebar collapsible="icon">
      <SidebarHeader className="h-16 flex-row items-center gap-3 border-b px-4">
        <div className="flex size-9 shrink-0 items-center justify-center rounded-lg bg-primary text-sm font-bold text-primary-foreground">
          EE
        </div>

        <div className="group-data-[collapsible=icon]:hidden">
          <div className="text-sm font-semibold">
            英语教学平台
          </div>
          <div className="text-xs text-muted-foreground">
            Teaching Management
          </div>
        </div>
      </SidebarHeader>

      <SidebarContent>
        <SidebarGroup>
          <SidebarMenu>
            {adminMenus.map((item) => {
              const active =
                pathname === item.href ||
                pathname.startsWith(`${item.href}/`);

              return (
                <SidebarMenuItem key={item.href}>
                  <SidebarMenuButton
                    render={<Link href={item.href} />}
                    isActive={active}
                    tooltip={item.title}
                  >
                    <Users />
                    <span>{item.title}</span>
                  </SidebarMenuButton>
                </SidebarMenuItem>
              );
            })}
          </SidebarMenu>
        </SidebarGroup>
      </SidebarContent>
    </Sidebar>
  );
}
```

### 5.2 理解客户端组件

首先看文件开头：

```tsx
"use client";
```

这是 Next.js 的客户端组件声明。

为什么这里需要客户端组件？

因为左侧菜单需要根据当前访问地址判断哪个菜单处于选中状态。

代码中使用了：

```tsx
const pathname = usePathname();
```

`usePathname()` 是 Next.js 提供的 Hook，用于获取当前页面的 URL 路径。

例如：

访问：

```text
/admin/users
```

得到的 `pathname` 就是：

```text
/admin/users
```

因为这里需要使用客户端 Hook，所以必须声明 `"use client"`。

### 5.3 理解组件导入

接下来：

```tsx
import Link from "next/link";
import { usePathname } from "next/navigation";
import { Users } from "lucide-react";
```

分别导入：

- `Link`：Next.js 的页面导航组件。
- `usePathname`：获取当前页面地址。
- `Users`：Lucide 提供的用户图标。

然后：

```tsx
import {
  Sidebar,
  SidebarContent,
  SidebarGroup,
  SidebarHeader,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
} from "@/components/ui/sidebar";
```

导入刚才通过 shadcn 安装的 Sidebar 组件。

这里使用的是项目中的组件文件，而不是从一个远程组件库中导入。

### 5.4 理解菜单配置的导入

```tsx
import { adminMenus } from "@/config/menu";
```

这里导入前面创建的菜单配置。

注意，侧边栏组件并没有自己定义菜单数据。

它只负责展示菜单。

这样，菜单数据和菜单界面就分离了。

### 5.5 理解菜单遍历

先看：

```tsx
{adminMenus.map((item) => {
```

这里使用 `map()` 遍历菜单数组。

每次遍历都会得到一个菜单对象。

例如：

```ts
{
  title: "用户管理",
  href: "/admin/users",
  icon: "users",
}
```

然后使用这个对象生成菜单界面。

### 5.6 理解菜单高亮

接下来：

```tsx
const active =
  pathname === item.href ||
  pathname.startsWith(`${item.href}/`);
```

这段代码用于判断菜单是否处于选中状态。

第一种情况：

```tsx
pathname === item.href
```

表示当前页面地址和菜单地址完全相同。

第二种情况：

```tsx
pathname.startsWith(`${item.href}/`)
```

表示当前页面是这个菜单下的子页面。

例如：

```text
菜单地址：/admin/users
当前地址：/admin/users/1001
```

虽然两个地址不完全相同，但当前页面仍然属于用户管理模块。

因此，用户管理菜单仍然应该保持选中状态。

### 5.7 理解 SidebarMenuButton

最后看菜单的 JSX：

```tsx
<SidebarMenuButton
  render={<Link href={item.href} />}
  isActive={active}
  tooltip={item.title}
>
  <Users />
  <span>{item.title}</span>
</SidebarMenuButton>
```

这里需要理解三个属性：

- `render`：指定使用 Next.js 的 Link 作为实际导航元素。
- `isActive`：设置当前菜单是否处于选中状态。
- `tooltip`：侧边栏收起时，鼠标悬停显示菜单名称。

`Link` 负责页面跳转，`SidebarMenuButton` 负责菜单按钮的样式和交互。

这里使用的是本项目 Sidebar 组件支持的 `render` 写法，不要将其他版本组件库的 `asChild` 写法直接套用进来。

至此，左侧菜单组件就完成了。

## 六、第四步：创建管理后台公共布局

现在已经有了菜单配置和左侧导航组件。

接下来需要将左侧导航与右侧内容区组合起来。

在 `app` 目录中创建：

```text
app/(dashboard)/
```

然后创建：

```text
app/(dashboard)/layout.tsx
```

这个文件是管理后台的公共布局。

### 6.1 编写完整代码

在 `layout.tsx` 中写入：

```tsx
import type { ReactNode } from "react";

import { AdminSidebar } from "@/components/layout/admin-sidebar";

import {
  SidebarInset,
  SidebarProvider,
  SidebarTrigger,
} from "@/components/ui/sidebar";

type DashboardLayoutProps = {
  children: ReactNode;
};

export default function DashboardLayout({
  children,
}: DashboardLayoutProps) {
  return (
    <SidebarProvider>
      <AdminSidebar />

      <SidebarInset>
        <header className="flex h-16 shrink-0 items-center gap-4 border-b px-6">
          <SidebarTrigger />

          <h1 className="text-sm font-semibold">
            英语教学平台管理后台
          </h1>
        </header>

        <main className="flex-1 overflow-auto bg-muted/30 p-6">
          {children}
        </main>
      </SidebarInset>
    </SidebarProvider>
  );
}
```

### 6.2 理解 children 的类型

先看：

```tsx
import type { ReactNode } from "react";
```

这里导入了 React 提供的 `ReactNode` 类型。

然后：

```tsx
type DashboardLayoutProps = {
  children: ReactNode;
};
```

定义了布局组件接收的参数类型。

为什么使用 `ReactNode`？

因为 `children` 可能是一个页面组件，也可能是多个 React 节点组成的内容。

`ReactNode` 可以表示 React 能够渲染的节点类型。

### 6.3 理解 Layout 组件

接下来：

```tsx
export default function DashboardLayout({
  children,
}: DashboardLayoutProps) {
```

这里定义了一个默认导出的 React 组件。

`export default` 表示其他模块不需要通过名称来导入它。

Next.js 对 `layout.tsx` 有约定：默认导出的组件就是当前路由分组的布局组件。

### 6.4 理解 SidebarProvider

接下来是：

```tsx
<SidebarProvider>
  ...
</SidebarProvider>
```

它是 shadcn Sidebar 组件体系的外层容器。

它负责管理侧边栏的展开和收起状态。

因此，`AdminSidebar` 和 `SidebarTrigger` 必须处于同一个 `SidebarProvider` 的组件环境中。

### 6.5 理解左右结构

```tsx
<AdminSidebar />

<SidebarInset>
  ...
</SidebarInset>
```

这两个组件分别负责页面的左右区域。

`AdminSidebar` 是我们刚才编写的左侧导航组件。

`SidebarInset` 是 shadcn Sidebar 提供的右侧主内容容器。

在 `SidebarInset` 内部，又分成顶部区域和页面内容区域：

```tsx
<header>
  <SidebarTrigger />
  <h1>英语教学平台管理后台</h1>
</header>

<main>
  {children}
</main>
```

顶部使用 `header`，内容区域使用 `main`。

其中：

```tsx
<SidebarTrigger />
```

负责控制左侧导航展开和收起。

而：

```tsx
{children}
```

就是当前页面的实际内容。

这就是公共布局最核心的部分。

## 八、第六步：访问根地址时自动跳转到用户管理

```tsx
import { redirect } from "next/navigation";
```

### 8.2 理解代码

首先：

```tsx
import { redirect } from "next/navigation";
```

从 Next.js 导入 `redirect` 函数。

接下来：

```tsx
redirect("/admin/users");
```

表示访问当前页面时，自动跳转到 `/admin/users`。

所以，当用户打开：


```text
http://localhost:3000/admin/users
```

这里不需要编写客户端跳转代码，也不需要使用 `useEffect`。

Next.js 已经提供了服务端重定向能力。
