# 第六篇：用户管理列表查询——从数据库读取用户数据

前面几篇已经完成了项目初始化、后台布局、导航菜单和 Git 版本管理。

现在访问 `/admin/users`，可以看到用户管理页面，但页面中还只有一段占位文字：

> 用户列表将在这里展示。

这一篇开始让页面真正具备业务功能：从 PostgreSQL 数据库读取用户数据，并展示在用户管理页面中。

本篇完成以下功能：

- 建立 PostgreSQL 数据库连接。
- 使用 Prisma 定义用户数据模型。
- 从数据库读取用户列表。
- 支持按姓名、用户名、邮箱和手机号搜索。
- 支持按账号状态筛选。
- 支持分页查询。
- 没有数据时显示空状态。

本篇暂时不实现用户新增、编辑、删除，也不引入登录认证和权限控制。先把最基础的数据读取流程理解清楚。

## 一、先理解：一个列表查询需要经过哪些环节？

在传统开发中，用户打开一个列表页面，通常会经历以下过程：

```text
浏览器访问 /admin/users
        |
        v
Next.js 页面接收请求
        |
        v
读取 URL 查询参数
        |
        v
校验搜索条件和分页参数
        |
        v
调用用户查询服务
        |
        v
Prisma 查询 PostgreSQL
        |
        v
返回用户数据
        |
        v
页面渲染表格
```

这里有几个基础概念需要先理解。

### 1. 什么是数据库模型？

数据库中存储的是结构化数据。

例如，一个用户可能包含以下信息：

| 字段 | 含义 |
|---|---|
| id | 用户唯一标识 |
| name | 姓名 |
| email | 邮箱 |
| username | 用户名 |
| phone | 手机号 |
| status | 账号状态 |
| createdAt | 创建时间 |

这些字段组成了一条用户记录。

数据库模型就是对这些数据结构的描述。通过模型，我们可以告诉 ORM：用户有哪些字段、字段是什么类型、哪些字段不能重复。

### 2. 什么是 ORM？

ORM 是 Object Relational Mapping，即对象关系映射。

它的作用是让开发者通过编程语言中的对象和方法操作数据库，而不必在每次查询时手写 SQL。

本项目使用 Prisma。

例如：

```ts
const users = await db.user.findMany();
```

这段代码就可以查询用户表中的记录。

Prisma 会根据模型定义生成对应的 TypeScript 类型和数据库操作接口。

### 3. 什么是分页查询？

假设数据库中有 1000 条用户记录，如果每次打开页面都把 1000 条数据全部读取出来，不仅浪费数据库资源，也会增加页面渲染负担。

因此通常采用分页。

例如：

- 每页显示 10 条。
- 第 1 页读取第 1～10 条。
- 第 2 页读取第 11～20 条。
- 第 3 页读取第 21～30 条。

Prisma 提供两个重要参数：

```ts
skip: 10,
take: 10,
```

其中：

- `skip`：跳过多少条记录。
- `take`：最多读取多少条记录。

第 2 页，每页 10 条：

```ts
skip: (2 - 1) * 10,
take: 10,
```

也就是跳过前 10 条，再读取 10 条。

### 4. 什么是 URL 查询参数？

列表页面通常需要记录当前的搜索条件和页码。

例如：

```text
/admin/users?keyword=张三&status=ACTIVE&page=2
```

这里：

- `keyword=张三`：搜索关键词。
- `status=ACTIVE`：只查询启用状态的用户。
- `page=2`：当前是第 2 页。

把查询条件放在 URL 中有几个好处：

1. 刷新页面后搜索条件不会丢失。
2. 可以复制链接，重新打开相同的查询结果。
3. 分页、搜索和筛选都可以通过服务端页面处理，不必额外开发一套 API。

本篇采用 Next.js App Router 的服务端组件读取查询参数。

## 二、安装 Prisma 和 PostgreSQL 驱动

当前项目已经安装了 Zod，但还没有 Prisma 和数据库驱动。

Prisma 7 使用数据库 Adapter 连接 PostgreSQL，因此需要安装以下依赖。

在项目根目录执行：

```bash
pnpm add @prisma/client @prisma/adapter-pg pg dotenv
pnpm add -D prisma
```

各个依赖的作用：

| 依赖 | 作用 |
|---|---|
| prisma | Prisma 命令行工具 |
| @prisma/client | 在业务代码中执行数据库操作 |
| @prisma/adapter-pg | Prisma 连接 PostgreSQL 的适配器 |
| pg | PostgreSQL Node.js 驱动 |

这里要区分两个概念：

- `prisma` 主要负责开发阶段的模型管理、迁移和代码生成。

安装完成后，执行：

```bash
pnpm exec prisma -v
```

确认 Prisma CLI 可以正常运行。

## 三、配置数据库连接

### 1. 准备 PostgreSQL 数据库

本地需要先有一个可以访问的 PostgreSQL 实例。

例如创建一个数据库：

```sql
CREATE DATABASE english_teaching;
```

数据库创建完成后，在项目根目录的 `.env` 文件中配置连接地址：

```env
DATABASE_URL="postgresql://postgres:你的数据库密码@localhost:5432/english_teaching?schema=public"
```

请根据自己的 PostgreSQL 用户名、密码、主机和端口修改连接字符串。

注意：`.env` 文件不能提交到 GitHub，数据库密码属于敏感信息。

### 2. 初始化 Prisma

执行：

```bash
pnpm exec prisma init --datasource-provider postgresql
```

Prisma 会初始化数据库相关文件。

本篇需要使用的主要文件是：

```text
prisma/
  schema.prisma

prisma.config.ts
```

### 3. 编写 Prisma 配置

打开项目根目录的 `prisma.config.ts`，完整修改为：

```ts
import "dotenv/config";
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: env("DATABASE_URL"),
  },
});
```

这段代码负责告诉 Prisma：

- 数据模型文件在哪里。
- 数据库迁移文件保存在哪里。
- 数据库连接地址从哪个环境变量读取。

Prisma 7 将数据库连接配置放到了 `prisma.config.ts` 中，而不是继续在 `schema.prisma` 的 datasource 中直接配置 `url`。

### 4. 编写用户数据模型

打开 `prisma/schema.prisma`，完整修改为：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../app/generated/prisma"
}

datasource db {
  provider = "postgresql"
}

enum UserStatus {
  ACTIVE
  DISABLED
}

model User {
  id            String     @id @default(cuid())
  name          String
  email         String     @unique
  emailVerified Boolean    @default(false)
  image         String?

  username      String?    @unique
  phone         String?
  status        UserStatus @default(ACTIVE)

  createdAt     DateTime   @default(now())
  updatedAt     DateTime   @updatedAt

  @@index([createdAt])
}
```

逐项理解这段模型。

**第一部分：生成 Prisma Client**

```prisma
generator client {
  provider = "prisma-client"
  output   = "../app/generated/prisma"
}
```

`provider` 指定 Prisma Client 的生成方式。

`output` 指定生成代码的目录。

本项目将生成的客户端放在：

```text
app/generated/prisma
```

因此后续数据库代码需要从这个目录导入 PrismaClient。

**第二部分：数据库类型**

```prisma
datasource db {
  provider = "postgresql"
}
```

这里指定使用 PostgreSQL。

数据库连接地址已经在 `prisma.config.ts` 中配置。

**第三部分：用户状态枚举**

```prisma
enum UserStatus {
  ACTIVE
  DISABLED
}
```

这里定义了两种用户状态：

- `ACTIVE`：启用。
- `DISABLED`：停用。

使用枚举类型，可以避免在业务代码中随意传入其他状态值。

**第四部分：User 模型**

```prisma
model User {
  id       String @id @default(cuid())
  name     String
  email    String @unique
  username String? @unique
}
```

几个常见标记：

- `@id`：主键。
- `@default(cuid())`：自动生成唯一标识。
- `@unique`：唯一约束。
- `String?`：允许字段为空。

例如邮箱设置了 `@unique`，意味着不能有两个用户使用同一个邮箱。

**第五部分：时间字段**

```prisma
createdAt DateTime @default(now())
updatedAt DateTime @updatedAt
```

`createdAt` 在创建记录时自动赋值。

`updatedAt` 在记录更新时自动维护。

这些字段在后台管理系统中非常常见。

### 5. 创建数据库表

模型编写完成后，执行：

```bash
pnpm exec prisma migrate dev --name init
```

这个命令会根据模型创建数据库迁移，并将迁移应用到本地数据库。

随后执行：

```bash
pnpm exec prisma generate
```

生成 Prisma Client。

如果执行成功，可以看到项目中出现：

```text
app/generated/prisma/
```

这里的文件由 Prisma 自动生成，不需要手动编写。

## 四、建立 Prisma 数据库连接

数据库模型已经准备好，接下来需要在 Next.js 项目中建立数据库连接。

新建文件：

```text
lib/db.ts
```

完整代码：

```ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "@/app/generated/prisma/client";

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
  throw new Error("DATABASE_URL 环境变量未配置");
}

const adapter = new PrismaPg({
  connectionString,
});

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const db =
  globalForPrisma.prisma ??
  new PrismaClient({
    adapter,
  });

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = db;
}
```

### 1. 创建 PostgreSQL Adapter

```ts
const adapter = new PrismaPg({
  connectionString,
});
```

这里创建 PostgreSQL 适配器。

Prisma 通过这个适配器与 PostgreSQL 驱动进行通信。

### 2. 创建 PrismaClient

```ts
export const db =
  globalForPrisma.prisma ??
  new PrismaClient({
    adapter,
  });
```

`PrismaClient` 是实际执行数据库查询的客户端。

我们将它导出为 `db`，后续业务代码都可以通过它访问数据库。

例如：

```ts
db.user.findMany();
```

### 3. 为什么使用 globalThis？

Next.js 在开发模式下会频繁进行热更新。

如果每次重新加载模块都创建一个新的数据库客户端，就可能产生过多数据库连接。

因此这里通过 `globalThis` 保存客户端实例。

```ts
const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};
```

它表示在全局对象上维护一个 PrismaClient 实例。

开发环境优先复用已有实例，避免重复创建。

## 五、定义用户列表查询参数

数据库连接已经完成，现在开始编写列表查询逻辑。

首先创建：

```text
features/users/schemas.ts
```

本篇暂时只需要列表查询的参数校验，因此完整代码如下：

```ts
import { z } from "zod";

export const userListQuerySchema = z.object({
  page: z.coerce.number().int().min(1).catch(1),

  pageSize: z.coerce
    .number()
    .int()
    .refine((value) => [10, 20, 50, 100].includes(value))
    .catch(10),

  keyword: z.string().trim().max(50).catch(""),

  status: z
    .enum(["ACTIVE", "DISABLED"])
    .optional()
    .catch(undefined),
});
```

这里使用了 Zod。

为什么需要校验？

因为 URL 参数是用户可以修改的。

例如用户可以直接在地址栏输入：

```text
/admin/users?page=-100
```

如果直接把这个参数交给数据库查询，就可能产生不合理的查询条件。

因此需要先校验。

### 1. z.coerce.number()

```ts
page: z.coerce.number().int().min(1).catch(1)
```

URL 中的参数本质上是字符串。

例如：

```text
?page=2
```

得到的是字符串 `"2"`。

`z.coerce.number()` 会尝试将它转换为数字。

后面的：

- `.int()`：要求必须是整数。
- `.min(1)`：最小值为 1。
- `.catch(1)`：转换或校验失败时回落到 1。

### 2. 限制每页条数

```ts
pageSize: z.coerce
  .number()
  .int()
  .refine((value) => [10, 20, 50, 100].includes(value))
  .catch(10)
```

这里使用 `refine()` 增加自定义校验。

每页只允许 10、20、50、100 条，其他值都回落到默认的 10 条。

这样可以防止用户通过修改 URL 一次请求大量数据。

### 3. 搜索关键词

```ts
keyword: z.string().trim().max(50).catch("")
```

关键词先去除首尾空格，再限制长度。

没有传入关键词或者校验失败时，使用空字符串。

### 4. 用户状态

```ts
status: z
  .enum(["ACTIVE", "DISABLED"])
  .optional()
  .catch(undefined)
```

状态可以不传。

不传代表查询全部状态。

如果传入的值不是允许的枚举值，则回落到 `undefined`，也就是不按状态过滤。

## 六、实现用户列表查询服务

现在创建：

```text
features/users/service.ts
```

完整代码：

```ts
import "server-only";

import { Prisma, UserStatus } from "@/app/generated/prisma/client";
import { db } from "@/lib/db";

type UserListParams = {
  page: number;
  pageSize: number;
  keyword: string;
  status?: UserStatus;
};

export async function getUserList(params: UserListParams) {
  const { page, pageSize, keyword, status } = params;

  const where: Prisma.UserWhereInput = {};

  if (keyword) {
    where.OR = [
      {
        name: {
          contains: keyword,
          mode: "insensitive",
        },
      },
      {
        username: {
          contains: keyword,
          mode: "insensitive",
        },
      },
      {
        email: {
          contains: keyword,
          mode: "insensitive",
        },
      },
      {
        phone: {
          contains: keyword,
        },
      },
    ];
  }

  if (status) {
    where.status = status;
  }

  const total = await db.user.count({
    where,
  });

  const totalPages = Math.max(
    1,
    Math.ceil(total / pageSize)
  );

  const currentPage = Math.min(
    Math.max(1, page),
    totalPages
  );

  const items = await db.user.findMany({
    where,

    select: {
      id: true,
      name: true,
      email: true,
      username: true,
      phone: true,
      status: true,
      createdAt: true,
    },

    orderBy: [
      { createdAt: "desc" },
      { id: "desc" },
    ],

    skip: (currentPage - 1) * pageSize,
    take: pageSize,
  });

  return {
    items,
    total,
    page: currentPage,
    pageSize,
    totalPages,
  };
}
```

这一部分是本篇最重要的业务代码。

### 1. 为什么导入 server-only？

```ts
import "server-only";
```

用户查询服务需要访问数据库。

数据库连接信息、数据库客户端都不应该被发送到浏览器。

`server-only` 可以帮助阻止这个模块被客户端组件意外导入。

因此，数据库服务应该放在服务端使用。

### 2. UserListParams 是什么？

```ts
type UserListParams = {
  page: number;
  pageSize: number;
  keyword: string;
  status?: UserStatus;
};
```

这是一个 TypeScript 类型定义。

它规定调用 `getUserList()` 时，需要提供哪些查询参数。

例如：

```ts
getUserList({
  page: 1,
  pageSize: 10,
  keyword: "张三",
});
```

这样可以在编译阶段检查参数是否符合要求。

### 3. Prisma.UserWhereInput 是什么？

```ts
const where: Prisma.UserWhereInput = {};
```

这是 Prisma 根据数据库模型生成的查询条件类型。

它告诉 TypeScript：`where` 中可以使用哪些字段和条件。

例如：

```ts
where.status = "ACTIVE";
```

或者：

```ts
where.name = {
  contains: "张三",
};
```

使用生成的类型，可以减少手写查询条件时的错误。

### 4. OR 多字段搜索

```ts
where.OR = [
  { name: { contains: keyword, mode: "insensitive" } },
  { username: { contains: keyword, mode: "insensitive" } },
  { email: { contains: keyword, mode: "insensitive" } },
  { phone: { contains: keyword } },
];
```

这里的 `OR` 表示多个条件满足其中一个即可。

例如搜索关键词为 `zhang`，那么：

- 姓名包含 `zhang`，可以匹配。
- 用户名包含 `zhang`，可以匹配。
- 邮箱包含 `zhang`，可以匹配。
- 手机号包含 `zhang`，可以匹配。

`contains` 表示包含查询。

`mode: "insensitive"` 表示忽略大小写。

这里的搜索条件会被组合成一个数据库查询，而不是把所有用户读取到内存中再进行筛选。

### 5. 状态筛选

```ts
if (status) {
  where.status = status;
}
```

如果传入了状态，就增加状态条件。

例如：

```ts
status = "ACTIVE";
```

最终查询条件就会同时包含关键词和状态。

这意味着关键词搜索和状态筛选可以组合使用。

### 6. 统计总数

```ts
const total = await db.user.count({
  where,
});
```

这里查询符合条件的用户总数。

注意：这里统计的是符合搜索条件和状态条件的总数，而不是数据库中所有用户的总数。

例如：

- 数据库中有 100 条用户记录。
- 搜索关键词匹配到 25 条。
- 状态筛选后剩余 15 条。

那么 `total` 就是 15。

### 7. 计算总页数

```ts
const totalPages = Math.max(
  1,
  Math.ceil(total / pageSize)
);
```

假设总记录数为 25，每页显示 10 条：

```ts
Math.ceil(25 / 10)
```

结果为 3。

这里使用 `Math.ceil()` 向上取整。

`Math.max(1, ...)` 则保证即使没有数据，也至少保留一个逻辑页码。

### 8. 防止页码超出范围

```ts
const currentPage = Math.min(
  Math.max(1, page),
  totalPages
);
```

例如用户原本在第 5 页，但搜索条件改变后只剩下 2 页数据。

如果仍然查询第 5 页，就会得到空结果。

因此需要把页码限制在有效范围内。

### 9. 查询当前页数据

```ts
const items = await db.user.findMany({
  where,
  select: {
    id: true,
    name: true,
    email: true,
    username: true,
    phone: true,
    status: true,
    createdAt: true,
  },
  orderBy: [
    { createdAt: "desc" },
    { id: "desc" },
  ],
  skip: (currentPage - 1) * pageSize,
  take: pageSize,
});
```

这里有几个重点：

**where**

使用前面组装的查询条件。

**select**

只读取页面需要的字段。

不要为了展示用户列表就把数据库中的所有字段全部返回。

**orderBy**

按照创建时间倒序排列。

第二个排序条件使用 `id`，用于在创建时间相同的情况下提供稳定排序。

**skip 和 take**

计算当前页需要跳过多少条数据，以及最多读取多少条数据。

最后返回：

```ts
return {
  items,
  total,
  page: currentPage,
  pageSize,
  totalPages,
};
```

页面就可以同时获得用户记录和分页所需要的信息。

## 七、实现用户列表页面

数据库查询服务已经完成，接下来需要把数据展示出来。

当前项目已经有 `Input` 组件，但还没有表格组件。

先执行：

```bash
pnpm dlx shadcn@latest add table
```

该命令会在 `components/ui` 中生成表格组件。

然后新建：

```text
features/users/components/user-list.tsx
```

完整代码：

```tsx
import Form from "next/form";
import Link from "next/link";

import { Badge } from "@/components/ui/badge";
import { Button, buttonVariants } from "@/components/ui/button";
import { Input } from "@/components/ui/input";

import {
  Table,
  TableBody,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from "@/components/ui/table";

import { userListQuerySchema } from "@/features/users/schemas";
import { getUserList } from "@/features/users/service";

type SearchParams = Promise<
  Record<string, string | string[] | undefined>
>;

export async function UserList({
  searchParams,
}: {
  searchParams: SearchParams;
}) {
  const params = await searchParams;

  const query = userListQuerySchema.parse(params);

  const {
    items,
    total,
    page,
    pageSize,
    totalPages,
  } = await getUserList(query);

  function buildHref(targetPage: number) {
    const search = new URLSearchParams();

    if (query.keyword) {
      search.set("keyword", query.keyword);
    }

    if (query.status) {
      search.set("status", query.status);
    }

    if (targetPage > 1) {
      search.set("page", String(targetPage));
    }

    const queryString = search.toString();

    return queryString
      ? `/admin/users?${queryString}`
      : "/admin/users";
  }

  return (
    <div className="space-y-4">
      <Form
        action="/admin/users"
        className="flex flex-wrap items-center gap-2"
      >
        <Input
          name="keyword"
          defaultValue={query.keyword}
          placeholder="搜索姓名、用户名、邮箱或手机号"
          className="max-w-xs"
        />

        <select
          name="status"
          defaultValue={query.status ?? ""}
          aria-label="按状态筛选"
          className="h-8 rounded-lg border border-input bg-transparent px-2.5 text-sm"
        >
          <option value="">全部状态</option>
          <option value="ACTIVE">启用</option>
          <option value="DISABLED">停用</option>
        </select>

        <Button type="submit">
          搜索
        </Button>

        <Link
          href="/admin/users"
          className={buttonVariants({
            variant: "outline",
          })}
        >
          重置
        </Link>
      </Form>

      <p className="text-sm text-muted-foreground">
        共 {total} 位用户
      </p>

      <div className="rounded-md border bg-card">
        <Table>
          <TableHeader>
            <TableRow>
              <TableHead>姓名</TableHead>
              <TableHead>用户名</TableHead>
              <TableHead>邮箱</TableHead>
              <TableHead>手机号</TableHead>
              <TableHead>状态</TableHead>
              <TableHead>创建时间</TableHead>
            </TableRow>
          </TableHeader>

          <TableBody>
            {items.map((user) => (
              <TableRow key={user.id}>
                <TableCell className="font-medium">
                  {user.name}
                </TableCell>

                <TableCell>
                  {user.username ?? "-"}
                </TableCell>

                <TableCell>
                  {user.email}
                </TableCell>

                <TableCell>
                  {user.phone ?? "-"}
                </TableCell>

                <TableCell>
                  <Badge
                    variant={
                      user.status === "ACTIVE"
                        ? "default"
                        : "secondary"
                    }
                  >
                    {user.status === "ACTIVE"
                      ? "启用"
                      : "停用"}
                  </Badge>
                </TableCell>

                <TableCell>
                  {user.createdAt.toLocaleString("zh-CN", {
                    timeZone: "Asia/Shanghai",
                  })}
                </TableCell>
              </TableRow>
            ))}

            {items.length === 0 && (
              <TableRow>
                <TableCell
                  colSpan={6}
                  className="h-24 text-center text-muted-foreground"
                >
                  暂无用户数据
                </TableCell>
              </TableRow>
            )}
          </TableBody>
        </Table>
      </div>

      <div className="flex flex-wrap items-center justify-between gap-3">
        <p className="text-sm text-muted-foreground">
          第 {page} / {totalPages} 页，每页 {pageSize} 条
        </p>

        <div className="flex items-center gap-2">
          <Link
            href={buildHref(page - 1)}
            aria-disabled={page <= 1}
            tabIndex={page <= 1 ? -1 : undefined}
            className={buttonVariants({
              variant: "outline",
              size: "sm",
            })}
          >
            上一页
          </Link>

          <Link
            href={buildHref(page + 1)}
            aria-disabled={page >= totalPages}
            tabIndex={page >= totalPages ? -1 : undefined}
            className={buttonVariants({
              variant: "outline",
              size: "sm",
            })}
          >
            下一页
          </Link>
        </div>
      </div>
    </div>
  );
}
```

### 1. 为什么 UserList 是 async 函数？

```tsx
export async function UserList({
  searchParams,
}: {
  searchParams: SearchParams;
}) {
```

因为组件内部需要等待数据库查询结果。

在 Next.js App Router 中，服务端组件可以直接使用 `async/await`。

不需要先编写一个 API 接口，再让浏览器通过 `fetch()` 获取数据。

### 2. 读取 searchParams

```tsx
const params = await searchParams;

const query = userListQuerySchema.parse(params);
```

Next.js 16 中，页面的 `searchParams` 是异步数据，需要使用 `await` 获取。

获取之后，再通过 Zod 解析。

这样页面拿到的 `query` 就是经过校验的查询参数。

### 3. 调用服务层

```tsx
const {
  items,
  total,
  page,
  pageSize,
  totalPages,
} = await getUserList(query);
```

页面不直接编写 Prisma 查询语句。

它只负责调用业务服务，并接收查询结果。

这样做的好处是职责清晰：

- 页面负责展示。
- Schema 负责参数校验。
- Service 负责业务查询。
- Prisma 负责数据库访问。

### 4. 为什么搜索表单使用 next/form？

```tsx
import Form from "next/form";
```

`next/form` 是 Next.js 提供的表单组件。

这里通过：

```tsx
<Form action="/admin/users">
```

提交搜索条件。

搜索表单中的 `name` 属性会成为 URL 查询参数。

例如：

```text
/admin/users?keyword=张三&status=ACTIVE
```

页面重新读取这些参数，查询对应的数据。

### 5. 为什么重置使用 Link？

```tsx
<Link href="/admin/users">
  重置
</Link>
```

重置实际上就是返回没有查询条件的列表页面。

不需要再编写一段客户端 JavaScript 清空表单。

### 6. 分页为什么也使用 URL？

```tsx
function buildHref(targetPage: number) {
  const search = new URLSearchParams();

  if (query.keyword) {
    search.set("keyword", query.keyword);
  }

  if (query.status) {
    search.set("status", query.status);
  }

  if (targetPage > 1) {
    search.set("page", String(targetPage));
  }

  const queryString = search.toString();

  return queryString
    ? `/admin/users?${queryString}`
    : "/admin/users";
}
```

这里重新构造分页链接。

特别需要注意：翻页时必须保留当前关键词和状态。

否则用户搜索某个姓名后，点击下一页就会丢失搜索条件。

## 八、将列表组件接入页面

现在修改原来的：

```text
app/(dashboard)/admin/users/page.tsx
```

完整代码：

```tsx
import { Suspense } from "react";

import {
  UserList,
} from "@/features/users/components/user-list";

export const instant = false;

type Props = {
  searchParams: Promise<
    Record<string, string | string[] | undefined>
  >;
};

export default function UsersPage({
  searchParams,
}: Props) {
  return (
    <div className="space-y-4">
      <div>
        <h2 className="text-2xl font-bold tracking-tight">
          用户管理
        </h2>

        <p className="mt-2 text-sm text-muted-foreground">
          管理平台用户，包括用户资料、账号状态和角色信息。
        </p>
      </div>

      <Suspense
        fallback={
          <div className="rounded-lg border bg-card p-6">
            正在加载用户列表...
          </div>
        }
      >
        <UserList searchParams={searchParams} />
      </Suspense>
    </div>
  );
}
```

这里保留了原来页面的标题和描述，只把原来的占位内容替换成了真正的用户列表。

### 为什么使用 Suspense？

```tsx
<Suspense fallback={...}>
  <UserList searchParams={searchParams} />
</Suspense>
```

`UserList` 需要等待数据库查询。

`Suspense` 可以在子组件等待时展示一个备用内容。

这样页面结构更加清晰，也为后续增加加载骨架屏做好准备。

## 十、运行和验证

启动项目：

```bash
pnpm dev
```

浏览器访问：

```text
http://localhost:3000/admin/users
```

正常情况下，可以看到用户列表。

接下来逐项验证。

### 1. 验证全部用户

访问：

```text
/admin/users
```

应该看到所有用户记录。

### 2. 验证关键词搜索

搜索：

```text
张
```

应该匹配姓名或用户名等字段中包含“张”的记录。

### 3. 验证状态筛选

选择：

```text
停用
```

应该只显示停用用户。

### 4. 验证组合查询

同时设置关键词和状态。

例如：

```text
/admin/users?keyword=张&status=DISABLED
```

应该只返回姓名、用户名、邮箱或手机号匹配“张”，并且状态为停用的用户。

### 5. 验证分页

当测试数据超过每页条数时，点击下一页。

观察：

- URL 中的页码是否变化。
- 当前列表是否更新。
- 搜索条件是否保留。
- 是否出现重复或遗漏记录。

### 6. 验证空数据

输入一个不存在的关键词。

页面应该显示：

```text
暂无用户数据
```

而不是报错。

## 十一、本篇小结

本篇完成了用户管理页面最基础的数据读取能力。

我们建立了以下调用关系：

```text
page.tsx
   |
   v
user-list.tsx
   |
   v
schemas.ts
   |
   v
service.ts
   |
   v
lib/db.ts
   |
   v
Prisma
   |
   v
PostgreSQL
```

这一套结构是后续开发管理后台的重要基础。

后面无论是用户列表、角色列表、学生列表，还是课程列表，都可以复用类似的设计思路。

本篇还需要特别理解三个知识点：

1. **服务端组件可以直接查询数据库。** 不必为了每一个列表页面都额外编写 API。
2. **查询条件应该由服务端校验。** 不能完全相信浏览器传来的 URL 参数。
3. **分页查询应该在数据库层完成。** 不应该先把全部数据读出来，再用 JavaScript 进行切片。

下一篇可以继续完善用户列表：增加更完整的分页组件、加载状态，以及用户列表的新增入口，为后面的用户新增功能做好准备。
