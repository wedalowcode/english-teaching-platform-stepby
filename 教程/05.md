# 第五篇：在腾讯云轻量应用服务器上搭建生产环境

## 一、本篇目标

前面几篇教程，我们已经完成了开发环境搭建、Next.js 项目初始化、后台基础布局，以及 Git 版本管理和 GitHub 代码托管。

目前代码运行在本地电脑上。为了让后续开发的系统能够通过公网访问，我们需要准备一台服务器，将本地开发环境与线上运行环境连接起来。

本篇使用腾讯云轻量应用服务器，搭建后续教程需要的生产环境。

本篇完成后，服务器将具备以下能力：

- 安装 Node.js，运行 Next.js 应用。
- 安装 pnpm，管理项目依赖。
- 安装 PostgreSQL，存储系统业务数据。
- 安装 Nginx，作为网站的 Web 访问入口。
- 配置服务器防火墙，控制公网访问端口。
- 准备项目部署目录，为后续代码部署做准备。

本篇暂时不部署英语教培平台的业务代码，下一阶段再将 GitHub 中的项目部署到服务器。

### 1.1 服务器配置

本教程使用的服务器配置如下：

| 项目 | 配置 |
|---|---|
| 云服务商 | 腾讯云 |
| 服务器类型 | 轻量应用服务器 |
| CPU | 2 核 |
| 内存 | 4GB |
| 操作系统 | Ubuntu Server 24.04 LTS |
| 架构 | 64 位 |
| 网络 | 公网 IP |
| 域名 | 暂不使用 |
| HTTPS | 暂不配置 |

服务器只有一个公网 IP，因此本阶段直接通过公网 IP 访问网站。

例如：

```text
http://你的服务器公网IP
```

后续如果购买域名并完成备案，再将域名解析到服务器，并配置 HTTPS。

## 二、开始之前：先理解生产环境

正式操作之前，先了解我们准备搭建的环境由哪些部分组成。

### 2.1 什么是开发环境？

开发环境就是我们平时写代码、调试代码的地方。

本项目使用 Trae 作为开发工具，项目运行在本地电脑上。

例如：

```text
本地电脑
  │
  ├── Trae
  │
  ├── Node.js
  │
  ├── pnpm
  │
  └── Next.js 项目
        │
        └── localhost:3000
```

在本地启动项目：

```bash
pnpm dev
```

浏览器访问：

```text
http://localhost:3000
```

这里的 localhost 指当前电脑，而不是互联网中的某台服务器。

因此，其他人无法直接通过这个地址访问我们电脑上的项目。

### 2.2 什么是生产环境？

生产环境是系统真正运行并向用户提供服务的环境。

当项目开发完成后，我们需要将代码部署到服务器，由服务器持续运行应用。

例如：

```text
用户浏览器
    │
    │ HTTP 请求
    ▼
腾讯云公网 IP
    │
    ▼
Nginx
    │
    │ 反向代理
    ▼
Next.js 应用
    │
    ▼
PostgreSQL 数据库
```

这里有几个重要概念。

**Node.js**

Node.js 是 JavaScript 的运行环境。

浏览器可以运行 JavaScript，但 Next.js 还有服务端代码，需要在服务器上运行。Node.js 就负责提供这个运行环境。

**PostgreSQL**

PostgreSQL 是关系型数据库，用来保存用户、角色、课程、学生、教学记录等业务数据。

**Nginx**

Nginx 是 Web 服务器，也可以作为反向代理。

用户访问公网 IP 时，首先到达 Nginx，再由 Nginx 将请求转发给 Next.js 应用。

**pnpm**

pnpm 是 JavaScript 项目的包管理工具。

我们在本地使用 pnpm 安装依赖，服务器部署时也使用 pnpm 安装项目依赖，保持开发与生产环境的一致性。

### 2.3 为什么需要 Nginx？

假设 Next.js 应用运行在服务器的 3000 端口。

理论上，用户可以直接访问：

```text
http://服务器公网IP:3000
```

但是生产环境通常不建议将应用服务直接暴露给公网。

我们采用下面的方式：

```text
用户
 │
 ▼
服务器公网 IP:80
 │
 ▼
Nginx
 │
 ▼
127.0.0.1:3000
 │
 ▼
Next.js
```

用户只需要访问：

```text
http://服务器公网IP
```

Nginx 会将请求转发到服务器内部的 Next.js 服务。

这样可以将公网入口与应用运行端口分开，也方便以后统一处理访问控制、请求转发和 HTTPS。

## 三、连接腾讯云服务器

### 3.1 获取公网 IP

登录腾讯云控制台，进入轻量应用服务器管理页面。

找到我们购买的服务器，查看公网 IP。

记录这个地址，后续连接服务器和访问网站都会用到。

### 3.2 连接服务器

可以使用腾讯云控制台提供的登录入口，也可以使用 Windows PowerShell 通过 SSH 连接。

打开 PowerShell，执行：

```bash
ssh ubuntu@你的服务器公网IP
```

这里的 ubuntu 是 Ubuntu 系统常见的默认登录用户名。如果实例控制台显示的默认用户名不同，以实际信息为准。

首次连接时，系统可能询问是否信任服务器指纹，确认服务器地址无误后输入：

```text
yes
```

随后根据服务器配置，使用密码或 SSH 密钥完成身份验证。

连接成功后，会看到类似下面的命令提示符：

```text
ubuntu@VM-xxxx:~$
```

这说明我们已经进入远程 Linux 服务器。

### 3.3 查看操作系统信息

执行：

```bash
cat /etc/os-release
```

可以看到系统发行版信息。

查看系统架构：

```bash
uname -m
```

如果返回：

```text
x86_64
```

说明当前是 64 位 x86 架构。

查看 CPU 和内存：

```bash
lscpu
```

```bash
free -h
```

至此，我们已经确认服务器的基本运行环境。

## 四、初始化服务器

新购买的服务器不应该直接开始部署项目，需要先更新系统并安装必要的基础工具。

### 4.1 更新软件包列表

Ubuntu 使用 apt 作为软件包管理工具。

先执行：

```bash
sudo apt update
```

这个命令会更新软件包索引，让系统获取当前软件仓库中的软件版本信息。

然后执行：

```bash
sudo apt upgrade -y
```

这个命令会升级已经安装的软件包。

其中：

- sudo：使用管理员权限执行命令。
- apt：Ubuntu 的软件包管理工具。
- upgrade：升级已经安装的软件。
- -y：自动确认安装过程中的提示。

### 4.2 安装常用工具

执行：

```bash
sudo apt install -y curl git ca-certificates gnupg openssl
```

这些工具的作用：

| 工具 | 用途 |
|---|---|
| curl | 下载文件、测试 HTTP 请求 |
| git | 从 GitHub 获取项目代码 |
| ca-certificates | 提供 HTTPS 证书验证所需的根证书 |
| gnupg | 验证软件仓库签名 |
| openssl | 提供加密和证书相关工具 |

后续安装 Node.js、获取项目代码和连接服务时都会用到这些工具。

### 4.3 设置服务器时区

服务器默认时区不一定是北京时间。

为了让日志、数据库记录和系统时间保持一致，设置时区：

```bash
sudo timedatectl set-timezone Asia/Shanghai
```

查看当前时间：

```bash
date
```

如果显示的是北京时间，说明设置成功。

## 五、配置服务器防火墙

服务器有公网 IP，就意味着互联网中的其他设备可以尝试连接服务器。

我们需要明确哪些端口允许外部访问。

### 5.1 理解端口

一个服务器可以同时运行多个服务，不同服务通过端口区分。

本项目涉及的主要端口：

| 端口 | 服务 | 公网是否开放 |
|---|---|---|
| 22 | SSH 远程连接 | 是 |
| 80 | HTTP 网站访问 | 是 |
| 443 | HTTPS 网站访问 | 暂不开放 |
| 3000 | Next.js | 否 |
| 5432 | PostgreSQL | 否 |

为什么不开放 3000 和 5432？

因为 Next.js 只需要接受 Nginx 转发过来的内部请求，数据库也只需要本机应用访问。

没有必要让互联网用户直接连接应用端口和数据库端口。

### 5.2 配置腾讯云防火墙

进入腾讯云轻量应用服务器控制台，找到服务器的防火墙配置。

添加入站规则：

| 协议 | 端口 | 来源 | 用途 |
|---|---|---|---|
| TCP | 22 | 你的管理 IP 或按实际管理需求设置 | SSH |
| TCP | 80 | 0.0.0.0/0 | HTTP 网站访问 |

如果管理 IP 不固定，SSH 来源规则需要结合实际登录环境设置。不要在没有其他可用登录方式时随意修改 SSH 访问规则。

暂时不添加 3000 和 5432 端口。

### 5.3 配置 Ubuntu 内部防火墙

腾讯云控制台的防火墙与 Ubuntu 系统内部的防火墙不是一回事。

Ubuntu 默认提供 UFW（Uncomplicated Firewall），可以通过简单命令管理系统防火墙。

先允许 SSH：

```bash
sudo ufw allow 22/tcp
```

再允许 HTTP：

```bash
sudo ufw allow 80/tcp
```

查看规则：

```bash
sudo ufw status
```

确认 SSH 和 HTTP 规则已经添加后，再启用防火墙：

```bash
sudo ufw enable
```

根据提示输入：

```text
y
```

再次检查：

```bash
sudo ufw status verbose
```

注意：一定要先允许 SSH，再启用防火墙，否则可能导致远程连接中断。

## 六、安装 Node.js

接下来安装 Next.js 运行所需要的 Node.js。

### 6.1 Node.js 是什么？

Node.js 是一个基于 Chrome V8 引擎的 JavaScript 运行环境。

我们编写的 React 组件最终会被 Next.js 组织成应用，而 Next.js 的服务端运行需要 Node.js 提供执行环境。

本项目使用 Node.js 24 LTS。

Ubuntu 24.04 自带的软件仓库可能提供较旧的 Node.js 版本，因此这里使用 NodeSource 软件仓库安装指定主版本。

### 6.2 配置 NodeSource 软件仓库

执行：

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x -o nodesource_setup.sh
```

这个命令会下载 Node.js 24 的软件仓库配置脚本。

执行脚本：

```bash
sudo -E bash nodesource_setup.sh
```

然后安装 Node.js：

```bash
sudo apt install -y nodejs
```

安装完成后，删除临时脚本：

```bash
rm nodesource_setup.sh
```

### 6.3 验证 Node.js

执行：

```bash
node -v
```

查看 Node.js 版本。

再执行：

```bash
node -e "console.log('Node.js 环境正常')"
```

如果输出：

```text
Node.js 环境正常
```

说明 Node.js 已经可以正常运行 JavaScript。

## 七、安装 pnpm

### 7.1 为什么服务器也需要 pnpm？

本地开发时，我们通过 pnpm 安装项目依赖。

例如：

```bash
pnpm install
```

将来把项目部署到服务器，也需要安装同样的依赖。

因此，服务器也需要准备 pnpm。

### 7.2 使用 Corepack 管理 pnpm

Corepack 是 Node.js 提供的包管理器版本管理工具，可以帮助我们启用和管理 pnpm。

执行：

```bash
corepack enable
```

激活包管理器支持。

然后执行：

```bash
corepack prepare pnpm@latest --activate
```

安装并激活 pnpm。

### 7.3 验证 pnpm

执行：

```bash
pnpm -v
```

如果能够显示版本号，说明 pnpm 安装成功。

后续部署项目时，应优先使用项目 `package.json` 中声明的 `packageManager` 版本，保证本地与服务器使用相同的包管理器版本。

## 八、安装 PostgreSQL 数据库

### 8.1 PostgreSQL 是什么？

PostgreSQL 是一个开源关系型数据库管理系统。

我们开发的英语教培平台需要保存大量结构化业务数据，例如：

- 用户和角色。
- 学生和教师。
- 课程和词汇。
- 教学记录。
- 学习报告。

这些数据需要保存在数据库中，而不是只保存在浏览器或服务器内存里。

项目使用 Prisma 作为 ORM，Prisma 负责连接数据库，并通过 TypeScript 代码完成数据读写。

整体关系如下：

```text
Next.js
   │
   ▼
Prisma
   │
   ▼
PostgreSQL
```

### 8.2 安装 PostgreSQL

Ubuntu 24.04 软件仓库提供 PostgreSQL 软件包。

执行：

```bash
sudo apt install -y postgresql
```

安装完成后，检查服务状态：

```bash
sudo systemctl status postgresql --no-pager
```

如果显示：

```text
active (exited)
```

或相关 PostgreSQL 集群处于运行状态，说明服务已经启动。Ubuntu 上的 PostgreSQL 服务可能通过集群管理机制运行，因此不要仅凭 `active (exited)` 就判断安装失败。

进一步查看集群状态：

```bash
pg_lsclusters
```

可以看到 PostgreSQL 集群的版本、端口和运行状态。

### 8.3 创建项目数据库用户

PostgreSQL 安装后，会创建一个默认的系统管理账户 postgres。

使用它进入数据库命令行：

```bash
sudo -u postgres psql
```

进入后，可以执行 SQL 命令。

先创建项目数据库用户：

```sql
CREATE ROLE english_app WITH LOGIN;
```

然后设置密码：

```sql
\password english_app
```

系统会提示输入两次密码。

这里请使用自己生成的高强度密码，并妥善保存。不要直接使用教程示例密码，也不要把真实密码提交到 GitHub。

创建项目数据库：

```sql
CREATE DATABASE english_teaching OWNER english_app;
```

查看数据库：

```sql
\l
```

退出数据库命令行：

```sql
\q
```

至此，我们已经创建了英语教培平台专用的数据库和数据库用户。

### 8.4 验证数据库连接

执行：

```bash
psql -h 127.0.0.1 -U english_app -d english_teaching -W
```

系统会要求输入刚才设置的数据库密码。

连接成功后，执行：

```sql
SELECT current_database(), current_user;
```

应该能够看到：

```text
current_database | current_user
-----------------+-------------
english_teaching | english_app
```

退出：

```sql
\q
```

这里的 `127.0.0.1` 表示服务器本机。

我们没有开放 PostgreSQL 的公网访问端口，后续 Next.js 应用通过服务器内部网络连接数据库即可。

## 九、安装 Nginx

### 9.1 安装 Nginx

执行：

```bash
sudo apt install -y nginx
```

安装完成后，检查服务状态：

```bash
sudo systemctl status nginx --no-pager
```

如果显示：

```text
active (running)
```

说明 Nginx 已经正常运行。

### 9.2 理解 Nginx 的工作方式

目前服务器上还没有部署 Next.js 应用。

我们先安装 Nginx，后续再配置它与 Next.js 之间的转发关系。

未来的请求流程是：

```text
浏览器
  │
  │ http://公网IP
  ▼
Nginx（80端口）
  │
  │ 转发到本机
  ▼
Next.js（3000端口）
  │
  ▼
PostgreSQL（5432端口）
```

Nginx 负责接收外部请求，Next.js 负责执行业务逻辑，PostgreSQL 负责保存业务数据。

### 9.3 验证 Nginx

在服务器上执行：

```bash
curl -I http://127.0.0.1
```

如果返回 HTTP 200 等正常响应，说明 Nginx 已经可以处理 HTTP 请求。

也可以直接在本地浏览器访问：

```text
http://你的服务器公网IP
```

如果看到 Nginx 默认欢迎页面，说明公网访问链路已经打通。

如果无法访问，依次检查：

1. 腾讯云控制台是否放行 TCP 80。
2. Ubuntu 的 UFW 是否允许 80 端口。
3. Nginx 是否处于运行状态。
4. 使用的公网 IP 是否正确。

## 十、准备项目部署目录

基础运行环境已经安装完成，现在准备项目未来存放的位置。

### 10.1 创建项目目录

执行：

```bash
sudo mkdir -p /var/www/english-teaching-platform
```

这里使用 `/var/www` 作为网站项目的存放目录。

将目录所有权交给当前登录用户：

```bash
sudo chown -R "$USER":"$USER" /var/www/english-teaching-platform
```

这样后续可以使用当前登录账户管理项目文件，而不必每次都使用 root 权限。

查看目录：

```bash
ls -ld /var/www/english-teaching-platform
```

### 10.2 为什么不直接使用 root 运行应用？

root 是 Linux 系统中的超级管理员账户，拥有很高的系统权限。

如果网站应用直接以 root 身份运行，一旦应用出现安全漏洞，可能造成更大的影响。

因此，生产环境应该使用普通用户运行应用。

本篇先完成项目目录准备。后续部署时，我们会进一步明确应用运行账户，并通过 systemd 管理 Next.js 进程。

最后统一检查各项服务。

### 11.2 检查 pnpm

```bash
pnpm -v
```

### 11.3 检查 PostgreSQL


### 11.4 检查 Nginx

重点观察：

```text
http://你的服务器公网IP
```

如果看到 Nginx 默认欢迎页面，说明我们已经通过公网成功访问了腾讯云服务器。

这一步非常重要：它验证了服务器、网络、防火墙和 Web 服务之间的基础链路。

```text
腾讯云轻量应用服务器
│
├── Ubuntu Server 24.04
│
├── Node.js 24
│
├── pnpm
│
├── PostgreSQL
│   └── english_teaching

└── /var/www/
    └── english-teaching-platform/
```

开发环境和生产环境现在已经有了明确的分工：

- 本地电脑：编写代码、调试功能、提交 Git 版本。
